# Dot Notation

Use dot-separated paths in `@Mapping(source: '...')` to extract fields from nested objects.

## Flattening Nested Objects

Access a nested field and map it to a flat target field:

```dart
class Address {
  final String street;
  final String city;
  const Address({required this.street, required this.city});
}

class Person {
  final String name;
  final Address address;
  const Person({required this.name, required this.address});
}

class FlatContact {
  final String name;
  final String street;
  final String city;
  const FlatContact({required this.name, required this.street, required this.city});
}

@Mapper()
abstract class ContactMapper {
  @Mapping(target: 'street', source: 'address.street')
  @Mapping(target: 'city', source: 'address.city')
  FlatContact toFlatContact(Person person);
}
```

Generated:

```dart
@override
FlatContact toFlatContact(Person person) {
  return FlatContact(
    name: person.name,
    street: person.address.street,
    city: person.address.city,
  );
}
```

## Nullable Intermediate Properties

When an intermediate property is nullable, the generator emits safe null-propagation (`?.`). The target field type must be compatible (nullable or have a `forceNonNull`):

```dart
class Person {
  final String name;
  final Address? address;  // nullable
  const Person({required this.name, this.address});
}

class FlatContact {
  final String name;
  final String? city;  // nullable target
  const FlatContact({required this.name, this.city});
}

@Mapper()
abstract class ContactMapper {
  @Mapping(target: 'city', source: 'address.city')
  FlatContact toFlatContact(Person person);
}
```

Generated:

```dart
@override
FlatContact toFlatContact(Person person) {
  return FlatContact(
    name: person.name,
    city: person.address?.city,
  );
}
```

## Deep Paths

Paths work at any depth:

```dart
@Mapping(target: 'postalCode', source: 'contact.address.location.postalCode')
ShippingLabel toLabel(Order order);
```

## Multi-Source with Dot Notation

Qualify the source parameter when using dot notation on multi-source methods:

```dart
@Mapper()
abstract class EmployeeMapper {
  @Mapping(target: 'city', source: 'company.hqAddress.city')
  EmployeeView toView(UserInfo user, CompanyInfo company);
}
```

## Map Paths

Dot notation also works when one side is a `Map`. With a Map source, each segment is a nested key and every intermediate level is treated as nullable:

```dart
@Mapping(source: 'address.street', target: 'street')
@Mapping(source: 'address.city', target: 'city')
Contact fromMap(Map<String, dynamic> map);
```

Generated:

```dart
street: (map['address'] as Map?)?['street'] as String,
city: (map['address'] as Map?)?['city'] as String,
```

A dot always means nesting, so a key containing a literal dot needs a `callable`.

For a class to Map method, source paths use `?.` on nullable intermediates (`'street': dto.address.street?.name`).

## Target Dot Notation (Class to Map)

When the **target** is a map, a dotted `target` builds nested maps and groups targets that share a prefix:

```dart
@Mapping(source: 'street', target: 'address.street')
@Mapping(source: 'city', target: 'address.city')
Map<String, dynamic> toMap(Contact contact);
```

Generated:

```dart
@override
Map<String, dynamic> toMap(Contact contact) {
  return {
    'name': contact.name,
    'address': {
      'street': contact.street,
      'city': contact.city,
    },
  };
}
```

## Dot Paths in Comma-Separated Sources

Each part of a comma-separated `source` can be a dot path. The parts are resolved as above and passed, in order, to a `callable` or to a mapper method (see the [Mapper Methods guide](/guides/mapper-methods)):

```dart
@Mapper(uses: {RouteMapper})
abstract class TripMapper {
  @Mapping(source: 'origin.city,destination.city', target: 'route')
  Trip toTrip(Booking booking);
}
```

Generated: `route: routeMapper.from(booking.origin.city, booking.destination.city)`.

A nullable link in a path (`origin?.city`) makes that argument nullable, so the parameter of the method must be nullable too (`Route from(String? origin, String destination)`). Otherwise the build fails and names the argument. A `callable` receives the same values and is type-checked by Dart.

## Target Dot Notation (Nested Target Objects)

When the **target** is a class, a dotted `target` builds the nested object of that class from flat source fields (or flat map keys). It works for class to class and Map to class methods:

```dart
class Contact {
  final String name;
  final String street;
  final String city;
  const Contact({required this.name, required this.street, required this.city});
}

class Address {
  final String street;
  final String city;
  const Address({required this.street, required this.city});
}

class StructuredContact {
  final String name;
  final Address address;
  const StructuredContact({required this.name, required this.address});
}

@Mapper()
abstract class ContactMapper {
  @Mapping(source: 'street', target: 'address.street')
  @Mapping(source: 'city', target: 'address.city')
  StructuredContact fromContact(Contact contact);

  @Mapping(source: 'street', target: 'address.street')
  @Mapping(source: 'city', target: 'address.city')
  StructuredContact fromMap(Map<String, dynamic> map);
}
```

Generated:

```dart
@override
StructuredContact fromContact(Contact contact) {
  return StructuredContact(
    name: contact.name,
    address: Address(
      street: contact.street,
      city: contact.city,
    ),
  );
}

@override
StructuredContact fromMap(Map<String, dynamic> map) {
  return StructuredContact(
    name: map['name'] as String,
    address: Address(
      street: map['street'] as String,
      city: map['city'] as String,
    ),
  );
}
```

Rules:

- A dotted target without a `source` reads the source property (or map key) named like its last segment: `@Mapping(target: 'address.zip', defaultValue: '0000')` reads `zip`.
- The nested object is built only from the targets you list. Its optional constructor parameters that are not mapped are left out, a required one that is not mapped fails with `NoRelationFoundError`.
- The nested object is always instantiated, even when its type is nullable.
- Paths can be nested more than one level (`location.geo.lat`).
- Every `@Mapping` option works on a dotted target: `source` (including dotted sources), `constant`, `expression`, `defaultValue`, `callable`, `forceNonNull`, `ignore` and `conditionExpression`.
- The classes along the path must be instantiable (not abstract without a factory, not sealed), and the mapper must be able to call their constructor: a private constructor of another library, or a class the mapper's file does not import, is a build error. Built Value classes, as root target or nested object, are not supported.
- Mapping both a whole property (`address`) and one of its sub-properties (`address.street`) is a build error (`InvalidNestedTargetError`), and so is an unknown property or an empty segment.
- `@InheritInverseConfiguration` of a flattening method (`source: 'address.street', target: 'street'`) generates the dotted target, so the inverse builds the nested object.

## Target Dot Notation (Class to Map)

When the **target** is a map, a dotted `target` builds nested maps and groups targets that share a prefix:

```dart
@Mapping(source: 'street', target: 'address.street')
@Mapping(source: 'city', target: 'address.city')
Map<String, dynamic> toMap(Contact contact);
```

Generated:

```dart
@override
Map<String, dynamic> toMap(Contact contact) {
  return {
    'name': contact.name,
    'address': {
      'street': contact.street,
      'city': contact.city,
    },
  };
}
```
