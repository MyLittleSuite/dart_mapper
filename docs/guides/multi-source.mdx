# Multi-Source Mapping

A mapper method can accept more than one source parameter. The generator resolves target fields from all sources automatically.

## Basic Multi-Source

Declare multiple parameters — the generator picks up fields from each:

```dart
class UserInfo {
  final String name;
  final int age;
  const UserInfo({required this.name, required this.age});
}

class CompanyInfo {
  final String companyName;
  final String department;
  const CompanyInfo({required this.companyName, required this.department});
}

class EmployeeProfile {
  final String name;
  final int age;
  final String companyName;
  final String department;
  const EmployeeProfile({
    required this.name,
    required this.age,
    required this.companyName,
    required this.department,
  });
}

@Mapper()
abstract class EmployeeMapper {
  EmployeeProfile toProfile(UserInfo user, CompanyInfo company);
}
```

Generated:

```dart
@override
EmployeeProfile toProfile(UserInfo user, CompanyInfo company) {
  return EmployeeProfile(
    name: user.name,
    age: user.age,
    companyName: company.companyName,
    department: company.department,
  );
}
```

## Resolving Ambiguity

If two source parameters have fields with the same name, the generator cannot resolve which to use and produces a build error. Use `@Mapping(source: 'paramName.fieldName')` to qualify:

```dart
class Primary {
  final String label;
  const Primary({required this.label});
}

class Secondary {
  final String label;
  const Secondary({required this.label});
}

class Result {
  final String label;
  const Result({required this.label});
}

@Mapper()
abstract class ResultMapper {
  @Mapping(target: 'label', source: 'primary.label')
  Result combine(Primary primary, Secondary secondary);
}
```

## Parameters as Sources

A parameter is a source too. It binds to the target property with the same name, so no `expression` is needed to forward it:

```dart
class CreateUser {
  final String name;
  const CreateUser({required this.name});
}

class UserDTO {
  final String id;
  final String name;
  const UserDTO({required this.id, required this.name});
}

@Mapper()
abstract class UserMapper {
  UserDTO fromCreate(CreateUser from, String id);
}
```

Generated:

```dart
@override
UserDTO fromCreate(CreateUser from, String id) {
  return UserDTO(id: id, name: from.name);
}
```

A parameter can also be named in `source`, including inside a comma-separated list (see the [Mapper Methods guide](/guides/mapper-methods)). Precedence, so existing mappers keep generating the same code:

1. an explicit `@Mapping`;
2. a property of a source parameter (the usual auto-mapping);
3. a parameter with the same name as the target.

If a bare `source: 'x'` names a parameter and also a property of another parameter, the ambiguity error above applies; qualify it (`source: 'param.x'`).

## Combining with @Mapping

Any `@Mapping` annotation applies to the combined view of all sources. Field renames, ignores, expressions, and dot-notation all work normally with multi-source methods:

```dart
@Mapper()
abstract class EmployeeMapper {
  @Mapping(target: 'displayName', expression: r'${user.name} @ ${company.companyName}')
  @Mapping(target: 'departmentCode', source: 'company.department')
  EmployeeProfile toProfile(UserInfo user, CompanyInfo company);
}
```

## Map Parameters

A `Map` can be one of the source parameters of a Map to class method:

```dart
@Mapper()
abstract class RoomMapper {
  RoomDTO fromRealtime(Map map, String id);
}
```

Unqualified names resolve **first** against the non-Map parameters, and the Map is the fallback for everything else. Use `map.k` (the parameter name followed by the key) to force a read from the map:

```dart
@Mapping(source: 'map.id', target: 'id')
RoomDTO fromRealtime(Map map, String id);
```

See the [Map Mapping guide](/guides/map-mapping) for the full rules.
